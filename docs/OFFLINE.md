# Experimental offline presentations

Hosted Cloudflare deployments can opt into the experimental offline editor by setting `ARTIFACT_STUDIO_EXPERIMENTAL_OFFLINE=1`. It is off by default. In the editor, **Save offline** saves the selected presentation on this device; **Saved presentations** opens the offline workspace. The browser must support IndexedDB, local storage, service workers and BroadcastChannel. Saved content and drafts are private browser data, so use a device and browser profile you trust.

The offline workspace saves static slide HTML, interactive source, the theme and up to 10 MB of local assets. It opens an isolated preview without network access and without running authored scripts, so interactive presentations may look incomplete. Symbolic links are refused, individual assets are limited to 5 MB, and at most 500 assets can be saved. Edits change static slide HTML; interactive source and speaker notes are preserved. This experimental scope does not yet provide the full visual editor offline.

Save an edit or comment to queue it with its original slide hashes and a server-issued receipt. **Reconnect and review** rechecks the signed-in identity and deck access before each delivery. If the same slide source changed online, review the original, current and offline versions and choose which to keep. If delivery is interrupted, the queue remains on the device for retry. A known sign-in or access failure blocks the saved source on later offline opens until access is verified again; queued drafts remain stored. A verified account switch clears the previous account's saved data. The editor's **Sign out** clears the offline data across tabs before signing out of Cloudflare. Signing out through the identity provider outside Studio does not invoke Studio's local purge; use Studio's sign-out control or clear site data on shared devices.

Offline receipts retain bounded source snapshots on the server and are bound to the verified provider, identity, workspace, deck, slide, hashes and comment channel. They are not standalone authorization: the server checks current permission on every write. The current experimental receipt quota is 500 slide receipts and 20 MB of retained source per identity; the server refuses new saves when full rather than deleting existing receipts. Offline edit recovery intents have a separate 20 MB limit. There is currently no receipt-management interface.
