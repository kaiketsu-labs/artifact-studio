# Experimental offline presentations

Hosted Cloudflare deployments can opt into the experimental offline editor by setting `ARTIFACT_STUDIO_EXPERIMENTAL_OFFLINE=1`. It is off by default. In the editor, **Save offline** saves or updates the selected presentation on this device. If you have queued changes, use **Saved presentations** to review and deliver them before replacing the saved copy. The browser must support IndexedDB, local storage, service workers and BroadcastChannel. Saved content and drafts are private browser data, so use a device and browser profile you trust.

The offline workspace saves static slide HTML, interactive source, the theme and up to 10 MB of local assets. It opens a sandboxed preview with authored scripts and network resource loads disabled, so interactive presentations may look incomplete. Symbolic links are refused, individual assets are limited to 5 MB, and at most 500 assets can be saved.

The first authorized offline request initializes receipt storage. Starting Studio with offline editing disabled leaves existing receipts and their schema untouched.

Click an object on the slide or choose it from **Slide object**. The text toolbar supports editing text, size, weight, italics, color and alignment. **Object options** lets you move, rotate or remove an object. Shift-click a direction to move farther. Choose **Save visual edit for later** to queue the result or **Cancel edit** to restore the object. Use **Slide HTML** for changes outside these controls. Visual edits change static slide HTML. Interactive source and speaker notes are preserved.

Save an edit or comment to queue it with its original slide hashes and a server-issued receipt. **Reconnect and review** rechecks the signed-in identity and deck access before each delivery. If the same slide source changed online, review the original, current and offline versions and choose which to keep. If delivery is interrupted, the queue remains on the device for retry. A known sign-in or access failure blocks the saved source on later offline opens until access is verified again; queued drafts remain stored. Choose **Recover my saved drafts** to view and copy only your own queued edits and comments without opening the saved presentation. A verified account switch clears the previous account's saved data. The editor's **Sign out** clears the offline data across tabs before signing out of Cloudflare. Signing out through the identity provider outside Studio does not invoke Studio's local purge; use Studio's sign-out control or clear site data on shared devices.

New offline copies use signed receipts. The server checks the identity, workspace, slide, revision, comment channel and current permissions on delivery. For an edit it also verifies the original HTML saved on the device. Repeated saves of the same revision issue the same receipt. A device that still carries an older receipt can deliver its drafts even after another device saves a newer copy.

Older saved copies continue to use their original server-side receipts. Reload an offline browser tab left open during an upgrade before starting new edits. The operator backup must include `sharing.sqlite3` to preserve receipt verification after restore. A regular workspace archive excludes that registry. Drafts issued after a restored backup can still be recovered on the originating device if receipt verification fails. Offline edit recovery retains up to 20 MB of pending original source per identity and releases that storage when delivery finishes.

Legacy receipt storage is normalized on upgrade: duplicate source blobs share one stored copy, and every old token remains usable. Repeated or concurrent legacy saves of the exact same source and original comment anchor reuse one receipt, including at the quota. The legacy limit is **500 distinct retained snapshots and 20 MB of source per identity**; new signed copies do not use this quota. Completed edit results remain available for retries even after their recovery source is reclaimed.

Migration is transactional. SQLite can reuse freed pages; the database file does not necessarily shrink immediately. Older application versions cannot write the normalized legacy receipt schema. Distinct legacy revisions remain retained because the server cannot know whether a disconnected device still needs them. Signed receipts avoid that cleanup problem for new saves: the device retains the original HTML and sends it with an edit, and the server verifies its signed digest. No expiration or another device's refresh deletes pending work. See the [repeated-save benchmark](performance/offline-receipts.md).
